# ページネーション UI コンポーネント — 調査結果まとめ

<!-- 過去の社内フレームワーク調査（beeworks-framework の pagination.astro）の観点を統合済み -->

## 1. コンポーネントの概要（What & Why）

### 定義・解決する問題

ページネーションは、大量の一覧コンテンツ（検索結果・記事一覧など）を複数のページに分割し、ページ間を移動するためのナビゲーション。1 ページの読み込み量を抑えつつ、全体の中の現在位置（何ページ目 / 全何ページ）を把握できるようにする。

構成要素: ページ番号リンク、前へ／次へリンク、（多ページ時の）省略記号、現在ページの表示。

### そもそも使うべきかの判断

一覧の分割手段は 3 つあり、ページネーションはその中で**最もアクセシビリティの担保が容易**（→ 下の比較表）。使用判断は「分割するか」より「無限スクロールにしない」が焦点になる。

- **無限スクロールの問題**（GOV.UK は明確に「使うな」。→ 参考記事 #5）:
  - キーボードユーザーは、読み込まれ続けるコンテンツを Tab で延々と通過しないとフッターに到達できない
  - スクリーンリーダーには新しいコンテンツの読み込みが伝わらない
  - 「どこまで見たか」「全体のどこか」が分からず、URL で位置を共有・復元できない。戻るで位置が失われる
- **「もっと見る」ボタン**は中間解。ユーザー操作起点なのでコントロールは保たれるが、追加読み込み後のフォーカス管理と件数通知は自前になる（→ 層 3「設計判断ポイント」）
- ページネーションが不要なケース: 件数が少なく 1 ページで足りる場合。フォーム等の直線的なフローの分割にはページネーションではなく「次へ」ボタン（GOV.UK）

### ネイティブ HTML 要素の有無

- 専用要素はないが、**`nav` + `ol` + `a` の素の HTML でほぼ完結する**。ARIA は `aria-label`（nav の識別）と `aria-current="page"`（現在位置）の 2 つだけが本質で、本書の中では最も「HTML だけで正しく作れる」側のコンポーネント
- サーバーサイドでページを分ければ **JS ゼロで成立する**のも特徴。SPA でクライアントサイド更新する場合にのみ、通知・フォーカスの追加要件が発生する（→ 層 2）

### 類似手段との使い分け

| 観点 | ページネーション | もっと見るボタン | 無限スクロール |
|------|-------------------|-------------------|-----------------|
| **現在位置の把握** | ページ番号で明確 | 曖昧 | 不可能 |
| **URL での共有・復元** | 可能（`?page=3`） | 不可（工夫すれば可） | 事実上不可 |
| **フッターへの到達** | 問題なし | 問題なし | 困難 |
| **キーボード・SR** | 標準リンクのみで完結 | フォーカス管理が必要 | 問題が多い |
| **実装コスト** | 最小（サーバーだけで可） | 中 | 高（やるほど問題が増える） |
| **向く場面** | 検索結果・アーカイブ | 同一ページで少しずつ見せたい一覧 | （SNS フィード等でも慎重に） |

## 2. アクセシブルであるためには（要件・規範）

### WCAG 2.2 該当基準の洗い出し

<!-- △ = 該当するか微妙だが念のため入れておく。詳細な要件・確認方法はチェック項目案側 -->

- **達成基準 2.4.4 リンクの目的（コンテキスト内）（レベル A）** — 「5」というリンクが「5 ページ目へのリンク」だと分かる
- **達成基準 1.1.1 非テキストコンテンツ（レベル A）** — 矢印アイコンだけの前へ／次へリンクに代替テキスト（過去調査でも指摘済みの観点）
- **達成基準 1.3.1 情報及び関係性（レベル A）** — `nav` によるナビゲーションの明示、`ol` によるリスト構造
- **達成基準 4.1.2 名前・役割・値（レベル A）** — `nav` の `aria-label`（他のナビゲーションとの区別）、`aria-current` による現在位置
- **達成基準 1.4.1 色の使用（レベル A）** — 現在ページの表示を色だけで区別しない
- **達成基準 2.1.1 キーボード（レベル A）** — 標準のリンクなら自動で満たせる（`div` + クリックイベントにしない）
- **達成基準 2.5.8 ターゲットのサイズ（最低限）（レベル AA）** ※WCAG 2.2 新規 — 数字リンクが密集して小さくなりがちな代表例。24×24 CSS ピクセル以上
- **達成基準 2.4.2 ページタイトル（レベル A）** — 分割された各ページのタイトルに「（3 ページ目）」等を含める（GOV.UK の推奨）
- △ **達成基準 4.1.3 ステータスメッセージ（レベル AA）** — SPA でページ内容だけ差し替える場合の結果更新の通知
- △ **達成基準 2.4.7 フォーカスの可視化（レベル AA）** — リンクのフォーカスリング
- △ **達成基準 1.4.10 リフロー（レベル AA）** — 狭い画面で番号があふれる（表示個数を絞る対応）
- △ **達成基準 3.2.3 一貫したナビゲーション（レベル AA）** — サイト内でページネーションの位置・形式を揃える

### キーボード操作仕様

規範パターンは APG に存在しない（標準リンクの集まりであり、専用のキーボード仕様が不要なため）。

| キー | 動作 |
|------|------|
| `Tab` / `Shift + Tab` | リンク間を順に移動（通常のリンクと同じ） |
| `Enter` | リンク先ページへ移動 |

- roving tabindex や矢印キーは**不要**。「ナビゲーション（リンクの集まり）」であって「ウィジェット」ではない、という区別はタブ章（`tablist` との対比）の裏返しとして書ける
- SPA でリンクではなくボタンで内容を差し替える場合は、更新の通知（4.1.3）とフォーカスの維持が追加で必要（→ フィルター章・リダイレクト章と共通の論点）

### ARIA ロールと属性

| 属性・要素 | 付与先 | 値・説明 |
|------------|--------|----------|
| `nav` 要素 | 全体のコンテナ | ナビゲーションランドマークにする |
| `aria-label` | `nav` | 「ページネーション」等。ページ内に複数の `nav` があるため識別必須 |
| `ol` 要素 | リンクのリスト | 順序に意味があるためリスト（`ol`）でマークアップ |
| `aria-current="page"` | 現在ページの要素 | 現在位置を支援技術に伝える |
| `aria-label` / 視覚的に隠すテキスト | 各番号リンク | 「5 ページ目」のように「ページ」の文脈を補う |
| `aria-label` | 前へ／次へリンク | 「前のページへ」「次のページへ」（アイコンのみの場合） |
| `rel="prev"` / `rel="next"` | 前後リンク | 意味の補強（GOV.UK が採用） |

補足:

- 番号リンクに `aria-label="5 ページ目"` を付ける場合、視覚ラベル「5」が名前に含まれるので 2.5.3（ラベルを含む名前）は問題ない。`aria-label` ではなく視覚的に隠したテキスト（「ページ」+ 表示される「5」）で組む方式もある
- 現在ページを**リンクにするか `span` にするか**は実装が割れている（→ 層 3「設計判断ポイント」）。どちらでも `aria-current="page"` は付ける

### WCAG 外のユーザビリティ要件

- **桁数の多いページ番号のデザイン確認**（過去の社内フレームワーク調査の観点）: 「999」等が入っても崩れないか。考慮すべき桁数は案件で異なるため、上限を決めてデザインする
- **省略記号（…）の扱い**: 省略記号はリンクではないので、**フォーカス可能にしない**（`span` + 必要なら読み上げ用テキスト）。過去のサンプルでは `a` 要素 + `aria-label="…"` になっており、「…」という名前のフォーカス可能要素が生まれていた。改善ポイントとして記事の NG 例に使える
- **狭い画面では表示する番号を絞る**: 現在ページ・前後・最初・最後だけにする（GOV.UK）
- **端のページでの前へ／次へ**: 最初のページで「前へ」を消す（GOV.UK）か、無効化して残すか（→ 設計判断ポイント）
- **全体像の提示**: 「1 … 99」のように最初と最後を常に見せると、総量の見当がつく

### チェック項目案（記事の単位に束ね直す）

#### 何ページ目へのリンクかが誰にでも伝わるようにする【本章固有】

- 該当基準: 2.4.4 リンクの目的、1.1.1 非テキストコンテンツ
- 要件: 番号リンクに「ページ」の文脈を付ける（`aria-label` または視覚的に隠すテキスト）。矢印アイコンのみの前へ／次へには「前のページへ」等の名前を付ける
- 確認方法: スクリーンリーダーのリンク一覧で「5、5」ではなく「5 ページ目」「次のページへ」と読まれるか

#### 現在のページがどれか、色以外でもわかるようにする【本章固有】

- 該当基準: 4.1.2 名前・役割・値、1.4.1 色の使用
- 要件: 現在ページに `aria-current="page"` を付け、視覚的にも色だけでなく塗り・枠・太字などで区別する
- 確認方法: スクリーンリーダーで「現在のページ、5」等と読まれるか。グレースケール表示で現在ページが判別できるか

#### ページネーションだと識別できるようにする【本章固有】

- 該当基準: 1.3.1 情報及び関係性、4.1.2
- 要件: `nav` 要素 + `aria-label="ページネーション"`。リンク群は `ol` でマークアップ。省略記号はフォーカス可能にしない
- 確認方法: スクリーンリーダーのランドマーク一覧に「ページネーション ナビゲーション」が現れるか。ヘッダーのナビゲーション等と区別できるか

#### 番号リンクを押しやすい大きさにする【本章固有】

- 該当基準: 2.5.8 ターゲットのサイズ（最低限）
- 要件: 各リンクの操作領域を 24×24 CSS ピクセル以上（望ましくは 44px 前後）。数字が 1 桁でも領域は確保する
- 確認方法: 最小のリンク（「1」等）の当たり判定を DevTools で計測
- 補足: 他章では見送りがちな 2.5.8 を、ページネーションでは主役級のチェック項目に格上げする（小さいターゲットが密集する、この基準の典型例のため）

#### ページタイトルにも現在のページ番号を含める【本章固有】【ユーザビリティ】

- 該当基準: 2.4.2 ページタイトル（適合というより品質向上）
- 要件: `<title>検索結果（3 ページ目 / 全 10 ページ）| サイト名</title>` のように、遷移後のタイトルで現在位置が分かるようにする
- 確認方法: ページを移動してブラウザタブのタイトルが変わるか。スクリーンリーダーがページロード時に読み上げる内容で位置が分かるか

#### キーボードで操作でき、フォーカスが見えるようにする【他章共通】

- 流用元: アコーディオン章「キーボードだけで開閉できる」「フォーカスインジケータが見える」項（リンクなので要件はより単純）
- 該当基準: 2.1.1 キーボード、2.4.7 フォーカスの可視化
- 確認方法: `Tab` で全リンクに到達でき、フォーカスリングが見えるか

#### 見送り（チェック項目にしない基準）

- **4.1.3 ステータスメッセージ** — SPA でのクライアントサイド更新をする場合のみ必要。本章の実装例はサーバーサイドページングを本筋にし、SPA の話はフィルター章に委譲する
- **1.4.10 リフロー** — 「狭い画面で表示個数を絞る」というユーザビリティ節の話として扱い、チェック項目にはしない
- **3.2.3 一貫したナビゲーション** — サイト全体の話。コンポーネント単体の章では扱わない（タブ章の 3.2.4 と同じ判断）

## 3. 具体事例（Evidence）

### 実装事例（デザインシステム）

| 項目 | GOV.UK | USWDS（米国 Web デザインシステム） | a11ymatters（解説） | 過去の社内フレームワーク |
|------|--------|-------------------------------------|----------------------|---------------------------|
| **コンテナ** | `nav` + `aria-label="Pagination"` | `nav` + `aria-label` | `nav` + `aria-label` | `nav` + `aria-label="ページネーション"` |
| **現在ページ** | リンク + `aria-current="page"` | リンク + `aria-current="page"` | `span`（リンクにしない）派の解説もあり | リンク + `aria-current="page"` |
| **番号のラベル** | `aria-label="Page 1"` | `aria-label` で「Page N」 | 「page」を補う | （番号のみ。改善余地） |
| **端の前へ／次へ** | 表示しない | — | — | （常時表示） |
| **省略記号** | リンクにしない | リンクにしない | — | `a` + `aria-label="…"`（改善余地） |
| **その他** | ページタイトルに番号、`rel` 属性、小画面で個数削減 | — | — | 桁数の多い場合のデザイン確認を明記 |

#### 設計判断ポイント（実装が割れている論点）

- **現在ページをリンクにするか `span` にするか** — リンク + `aria-current`（GOV.UK・USWDS）と、リンクにしない `span` + `aria-current`（tempertemper 等）で割れる。リンク派は「その場リロードできる・マークアップが均一」、非リンク派は「今いるページへのリンクは無意味でユーザーを混乱させる」。どちらも `aria-current` は共通なので、記事では両論併記 + どちらかを推奨
- **端のページで前へ／次へを消すか、無効化して残すか** — 消す（GOV.UK）とレイアウトが動く、残すと「無効なリンク」の表現問題（`a` に disabled はない。`a` から `href` を外す＝フォーカス不能な a、または `aria-disabled`）が発生する。「消す + レイアウトは CSS で固定」が扱いやすい
- **「もっと見る」ボタンを採る場合のフォーカス管理** — 追加読み込み後、フォーカスを新規項目の先頭に移す（またはボタンに留めて件数を 4.1.3 で通知する）。放置するとキーボードユーザーは追加分の先頭まで戻れない
- **SPA でのページ切り替え** — URL（クエリパラメータ）を必ず同期させる。しないと共有・復元・戻るが全滅する（リダイレクト章の SPA 遷移 3 点セットと同じ話）

### 失敗事例（ありがちな NG 例）

<!-- 候補ベース。執筆前にコード例化と裏取りをする -->

- **NG: 矢印アイコンだけの前へ／次へに名前がない**
  - 対応する要件: 1.1.1 非テキストコンテンツ、2.4.4
  - 何が起きるか: スクリーンリーダーで「リンク」としか読まれず、押した結果が予測できない
- **NG: 現在ページが色の違いだけ**
  - 対応する要件: 1.4.1 色の使用、4.1.2（`aria-current` なし）
  - 何が起きるか: 色覚特性によっては現在位置が見えず、スクリーンリーダーにはそもそも伝わらない
- **NG: 省略記号（…）がフォーカス可能なリンクになっている**
  - 対応する要件: 2.4.4（目的のないリンク）
  - 何が起きるか: 「…」という謎のリンクが Tab 順に現れる。押しても何も起きない
  - 出典・実例: 過去の社内フレームワークのサンプルにもこの形が残っていた（`a` + `aria-label="…"`）。ありがちな実例として使える
- **NG: 数字リンクが小さすぎて押せない**
  - 対応する要件: 2.5.8 ターゲットのサイズ
  - 何が起きるか: 手の震えがあるユーザーやタッチ操作で隣のページを誤タップする
- **NG: `div` + クリックイベントのページ番号**
  - 対応する要件: 2.1.1 キーボード、4.1.2
  - 何が起きるか: キーボードで到達できず、リンクとしても伝わらない。URL も変わらないため共有・復元も不可
- **NG: 無限スクロールでフッターに到達できない**
  - 対応する要件: 2.1.1（実質的な操作不能）、使用判断（層 1）
  - 何が起きるか: キーボード・スクリーンリーダーのユーザーはフッターのリンクに永遠に辿り着けない
- **NG: SPA でページを切り替えても何も通知されず、URL も変わらない**
  - 対応する要件: 4.1.3 ステータスメッセージ、2.4.2
  - 何が起きるか: スクリーンリーダーには何が起きたか伝わらず、リロードすると 1 ページ目に戻る

### 新しいブラウザ機能

該当なし（素の HTML で完結するコンポーネントであり、これ自体が「新機能に頼らない」見本になる）。

### フォールバック・不採用案

#### フォールバック: サーバーサイドページングが最も単純で堅牢

- ページネーションは「フォールバック不要」な側のコンポーネント。`?page=3` をサーバーで処理し、素のリンクを返す構成が JS ゼロで全要件を満たす
- むしろページネーション自体が、無限スクロール・「もっと見る」の**フォールバック先**になる

#### 不採用: 無限スクロール

**最大の問題: キーボード・スクリーンリーダーのユーザーがコンテンツの終端（フッター）に到達できず、現在位置の把握・共有もできない。**

**その他の問題:**

- 戻る操作で位置が失われる。パフォーマンス（DOM 肥大）も悪化する
- 採用するなら「もっと見る」ボタン起点に置き換え、フォーカス管理と件数通知を実装する（それでもページネーションより要件が多い）
