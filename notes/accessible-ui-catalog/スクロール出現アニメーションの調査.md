## 1. テクニックの概要（What & Why）

### 定義・解決する問題

スクロール出現アニメーションは、要素がビューポートに入ったタイミングでフェードイン・スライドイン等の演出を付けるテクニック。ページに動きとリズムを与える純粋な装飾で、機能的な必然性はない。

付随するテクニックとして **cloak（JS 実行まで非表示にする仕組み）**がある。JS の初期化前に「アニメーション開始前の状態」が一瞬見えてしまうチラツキ（FOUC）を防ぐために、過去実装では `data-cloak` で初期非表示にし、JS 到着後にアニメーションで表示していた。

この章の本質的な問い: **「装飾のために、コンテンツの知覚可能性をどこまで賭けてよいか」**。アニメーション自体より、「隠す」実装の仕方が事故の源泉になる。

### そもそも使うべきかの判断

- **完全に装飾**なので、「使わない」がいつでも正解になれる。判断材料:
  - 前庭障害・動揺病のユーザーには、スクロールに連動して動く要素そのものが体調不良の原因になる（`prefers-reduced-motion` 対応は必須であって十分ではない）
  - 出現を待たせる分、コンテンツへの到達は確実に遅くなる。速読するユーザー・高速スクロールするユーザーには「まだ表示されていないページ」に見える
  - LCP（ファーストビューの要素を opacity: 0 で始めると計測・体感の両方が悪化）や CLS への影響
- 使ってよい場面: マーケティング的な演出が価値になるページ（LP 等）の、**ファーストビュー外の・本文でない**要素。本文・ナビゲーション・フォームには使わない
- 「JS が失敗したら永久に見えない」構造（cloak の副作用）を持ち込むことになる点は、装飾のコストとして最初に認識する（→ 層 2）

### ネイティブ（プラットフォーム標準）手段の有無

- 従来は JS 必須だった（IntersectionObserver + クラス付与、または GSAP / ScrollTrigger 等のライブラリ。過去実装は GSAP）
- 現在は **CSS Scroll-driven Animations（`animation-timeline: view()`）**で、スクロール出現を CSS だけで書ける段階に来ている（Chrome 115〜。→ 層 3「新しいブラウザ機能」）。CSS 実装なら「JS が失敗して見えない」リスクが構造的に消えるため、このテクニックの最大の弱点への回答になる

### 類似テクニックとの使い分け

| 観点 | スクロール出現（1 回だけ） | スクロール連動（進捗連動） | ページロード時のアニメーション |
|------|-----------------------------|------------------------------|--------------------------------|
| **トリガー** | ビューポート進入 | スクロール量に追従 | ページ読み込み |
| **動きの量** | 小（1 回で終わる） | 大（スクロール中ずっと動く） | 小 |
| **前庭障害への負荷** | 中 | **高**（パララックス等） | 中 |
| **実装** | IntersectionObserver / `view()` | scroll イベント / `scroll()` タイムライン | CSS animation |

- スクロール量に追従し続けるパララックス系は、出現アニメーションより負荷が一段高い。本章では「1 回出現して終わる」型を主対象とし、パララックスは「より慎重に」とだけ触れる

## 2. アクセシブルであるためには（要件・規範）

### WCAG 2.2 該当基準の洗い出し

<!-- △ = 該当するか微妙だが念のため入れておく。詳細な要件・確認方法はチェック項目案側 -->

- **達成基準 2.3.3 インタラクションによるアニメーション（レベル AAA）** — 中核基準。スクロール（インタラクション）に起因するモーションを無効化できる（過去調査が唯一明記していた基準。AAA だが、このテクニックでは実質必須と扱う）
- **達成基準 1.1.1〜の知覚可能性全般（実装方式の問題として）** — 「隠し方」を誤ると、スクリーンリーダー・ページ内検索・キーボードからコンテンツが消える（過去調査の中核的知見。→ 下記）
- **達成基準 2.1.1 キーボード（レベル A）** — 未出現領域にフォーカス可能要素がある場合、`visibility: hidden` / `display: none` で隠すとフォーカス到達不能になる
- **達成基準 2.2.2 一時停止、停止、非表示（レベル A）** — △ 出現後も動き続ける演出（ループアニメーション）を伴う場合のみ
- **達成基準 2.3.1 3 回の閃光（レベル A）** — △ フラッシュを伴う演出をする場合のみ
- △ **達成基準 1.4.10 リフロー（レベル AA）** — transform でずらした要素が狭幅ではみ出す場合

#### 過去調査の中核的知見: 「隠すのは `opacity` だけにする」

過去の社内フレームワーク調査がこのテクニックについて残していた最重要の知見（scroll-show.astro より）:

> アニメーションが、読み上げやキーボード操作に影響しないように注意してください。単に `opacity` を変更すればよく、`visibility: hidden;` や `display: none;` にする必要はありません。もしそのように非表示にしてしまった場合、読み上げられなくなったり、キーボード操作で到達不可能になる可能性があります。

| 隠し方 | 見た目 | スクリーンリーダー | キーボード | ページ内検索 |
|--------|--------|---------------------|------------|---------------|
| `opacity: 0` | 見えない | **読める** | **到達できる**（リンク等があると「見えないのにフォーカス」問題は残る） | ヒットする |
| `visibility: hidden` | 見えない | 読めない | 到達できない | ヒットしない |
| `display: none` | 見えない | 読めない | 到達できない | ヒットしない |

- つまり「視覚的な演出のために視覚以外のチャネルまで隠すな」が原則。`opacity`（+ `transform` の移動）だけで演出する
- 補足: `opacity: 0` の領域にリンクやボタンが含まれる場合、「見えない要素にフォーカスが当たる」逆問題が生じる。**フォーカス可能要素を含むブロックには出現アニメーションを適用しない**のが最も安全（適用するならフェード時間を短くし、フォーカスで即時表示にする）

### cloak（JS 実行まで非表示）の安全設計

cloak は「JS が動くまで `opacity: 0`」にする仕組みなので、**JS が読み込めない・実行前に壊れた場合、コンテンツが永久に見えない**リスクを構造的に持つ。安全装置なしで使ってはいけない:

- **CSS を「JS が動いた証拠」で条件付けする**: `data-cloak { opacity: 0 }` を無条件に書くのではなく、`html.js .cloak { opacity: 0 }` のように JS が付与したクラス配下でのみ隠す（JS が来なければ最初から表示）
- **`prefers-reduced-motion` では cloak 自体を無効化**（隠さない・動かさない）
- **タイムアウトの保険**: 一定時間で強制表示する CSS animation（`animation: reveal 0s 3s forwards` 等）を仕込む方法もある
- CSS Scroll-driven Animations に移行すると、この問題は丸ごと消える（`@supports` で対応ブラウザだけに適用するため、非対応・失敗時は常に表示側に倒れる）

### WCAG 外のユーザビリティ要件

- **`prefers-reduced-motion` の実装粒度**: 「アニメーションを消す」のであって「コンテンツを消す」のではない。reduce 時は最初から表示（opacity: 1・transform なし）にする
  - ライブラリ利用時は何が無効化されるかを確認する（カルーセル章の Splide の例と同じ論点。過去実装の GSAP は自前で分岐が必要）
- **移動距離・時間を控えめに**: 長い距離をゆっくり動かすほど「待たされ感」と前庭負荷が増える。20〜40px・0.3〜0.6s 程度の小さな演出に留める
- **グループの順次出現（stagger）**: 過去実装にあった `data-scroll-group-show`。項目数が多いと最後の項目の表示が大きく遅れる。遅延の上限を設ける
- **LCP への配慮**: ファーストビュー内の要素（特にヒーロー画像・見出し）には適用しない
- **印刷**: `opacity: 0` のまま印刷されないか（print メディアで解除）

### チェック項目案（記事の単位に束ね直す）

#### 隠すのは opacity だけにする（読み上げ・検索・フォーカスを殺さない）【本章固有】

- 該当基準: 2.1.1、（1.1.1 以下の知覚可能性全般）
- 要件: 出現前の状態は `opacity: 0`（+ `transform`）のみで表現し、`visibility: hidden` / `display: none` を使わない。フォーカス可能要素を含むブロックには適用しない
- 確認方法: 出現前の領域のテキストをページ内検索でヒットさせられるか。スクリーンリーダーで（スクロールせずに）読み進められるか

#### prefers-reduced-motion でアニメーションを無効化する【他章共通】

- 流用元: アコーディオン章「モーションアニメーションを無効にできる」項（本章では AAA だが実質必須の扱い）
- 該当基準: 2.3.3 インタラクションによるアニメーション
- 要件: reduce 時は cloak も含めて無効化し、最初からすべて表示された状態にする
- 確認方法: OS の「視覚効果を減らす」設定でページを開き、スクロールしても何も動かず・すべて見えているか

#### JS が失敗してもコンテンツが見えるようにする【本章固有】

- 該当基準: なし（堅牢性の実務要件）
- 要件: cloak の CSS は「JS が動いた証拠」（JS が付与するクラス）配下でのみ有効にする。JS が読み込めない環境では最初から表示される
- 確認方法: DevTools で JS を無効化してページを開き、すべてのコンテンツが表示されるか

#### 演出を本文・操作 UI に適用しない【本章固有】【ユーザビリティ】

- 該当基準: なし（適用範囲の設計判断）
- 要件: 適用対象は装飾的なブロックに限定。ナビゲーション・フォーム・本文の読み物・ファーストビューの主要素には適用しない
- 確認方法: 演出対象の一覧を見て、「これが 3 秒見えなくても困らないか」で判定する

#### 見送り（チェック項目にしない基準）

- **2.2.2 一時停止、停止、非表示** — 1 回で終わる出現アニメーションは対象外。ループ演出を足す場合の注意として一言（カルーセル章参照）
- **2.3.1 3 回の閃光** — フラッシュ演出をしない前提。扱わない
- **1.4.10 リフロー** — transform の移動量が小さければ実害がない。移動距離の推奨値（ユーザビリティ節）に吸収

## 3. 具体事例（Evidence）

### 実装方式の比較

| 項目 | GSAP + ScrollTrigger（過去実装） | IntersectionObserver + CSS クラス | CSS Scroll-driven Animations |
|------|-----------------------------------|-------------------------------------|-------------------------------|
| **JS 依存** | ライブラリ + 初期化 | 小さな自前 JS | **なし** |
| **JS 失敗時** | cloak の安全設計が必須 | 同左 | 構造的に安全（非対応なら表示） |
| **reduce 対応** | 自前で分岐 | 自前で分岐（メディアクエリで CSS 側に寄せられる） | `@media not (prefers-reduced-motion)` で宣言的 |
| **stagger（順次出現）** | 得意 | `transition-delay` で可能 | `animation-delay` 等で可能 |
| **対応ブラウザ** | 全部 | 全部 | Chrome 115〜 / Safari 26〜、Firefox はフラグ付き（2026 年 7 月時点） |

#### 設計判断ポイント

- **一度出たら出しっぱなしにするか、スクロールで戻したら再度隠すか** — 再度隠す（リバース）は「読んでいた要素が消える」体験になるため、**出しっぱなし（1 回だけ）が基本**
- **適用範囲の線引き** — セクション単位のまとまった演出か、要素単位の細かい演出か。細かくするほど「まだ出てない要素」への遭遇率が上がる
- **stagger の遅延上限** — 項目が可変のリストでは、遅延の合計に上限を設ける（後半は同時に出す）

### 失敗事例（ありがちな NG 例）

<!-- 候補ベース。執筆前にコード例化と裏取りをする -->

- **NG: `visibility: hidden` / `display: none` で出現前を隠す**
  - 対応する要件: 2.1.1、知覚可能性全般
  - 何が起きるか: スクリーンリーダーで読めない・ページ内検索でヒットしない・フォーカスできない。「スクロールしないと DOM 上も存在しない」ページになる（過去調査が明示的に警告していた失敗）
- **NG: JS が読み込めないとページが白紙（cloak の安全装置なし）**
  - 対応する要件: 堅牢性の実務要件
  - 何が起きるか: CDN 障害・スクリプトエラー・省データモードで、コンテンツ全体が `opacity: 0` のまま残る
- **NG: `prefers-reduced-motion` を無視してスライドインし続ける**
  - 対応する要件: 2.3.3
  - 何が起きるか: 前庭障害のユーザーがページを読み進められない。設定で意思表示しているユーザーへの無視は信頼を直接損なう
- **NG: 本文やフォームまで出現アニメーションの対象にする**
  - 対応する要件: 適用範囲の設計（実害は 2.1.1・読書体験）
  - 何が起きるか: 速いスクロールで「白いページ」を見せられる。フォーカスが「まだ見えないボタン」に当たる
- **NG: ファーストビューのヒーロー要素を `opacity: 0` から始める**
  - 対応する要件: パフォーマンス（LCP）
  - 何が起きるか: 最大コンテンツの描画が遅延扱いになり、体感・計測の両方が悪化する
- **NG: reduce 設定でアニメーションだけでなくコンテンツも消える**
  - 対応する要件: 2.3.3 の誤実装
  - 何が起きるか: 「アニメーションを無効化」のつもりで「表示のトリガー」ごと無効化し、reduce ユーザーにだけコンテンツが見えない

### 新しいブラウザ機能: CSS Scroll-driven Animations（`animation-timeline: view()`）

```css
@media not (prefers-reduced-motion) {
  @supports (animation-timeline: view()) {
    .reveal {
      animation: fade-in linear both;
      animation-timeline: view();
      animation-range: entry 0% entry 100%;
    }
  }
}
@keyframes fade-in {
  from { opacity: 0; translate: 0 24px; }
}
```

- **何ができるか**: ビューポート進入（`view()` タイムライン）を CSS だけで検知してアニメーションできる。IntersectionObserver・GSAP・cloak の役割を丸ごと置き換える
- **アクセシビリティ上の本質的な利点**: `@supports` + メディアクエリで囲むため、**非対応ブラウザ・JS 無効・reduce 設定のすべてで「最初から表示」側に倒れる**。cloak が抱えていた「失敗したら見えない」リスクが構造的に消える
- **対応状況（2026 年 7 月時点）**: Chrome / Edge 115〜（2023 年）、Safari 26〜（2025 年）。Firefox はフラグ付き実装（Nightly では既定で有効）。caniuse ベースで約 85%
- **注意点**: Firefox 対応時の互換性として `animation-duration` に非ゼロ値が必要になる既知の癖がある。スクロール量に完全連動させる（`animation-range` を広く取る）と「スクロールを戻すと消える」動きになるため、出現型では range を狭く取るか `animation-fill-mode: both` で終端固定する
- **チャプターでの扱い方**: 対応率が既に高く「失敗時に安全側へ倒れる」性質のため、**本章では新機能を実装例の第一候補**にできる（他章の「JS 版が本筋」と逆の判断ができる珍しい例）。JS 版（IntersectionObserver）はフォールバックというより「全ブラウザで演出したい場合の追加実装」の位置づけ

### フォールバック・不採用案

#### フォールバック: アニメーションしない

- 純装飾なので「やらない」が常に成立する。特に判断に迷う要素（本文・フォーム・重要な画像）は、迷った時点で対象から外す

#### 不採用: `visibility` / `display` を切り替える実装

**最大の問題: 視覚演出のためにスクリーンリーダー・検索・フォーカスからもコンテンツを消してしまう。**（過去調査が明示的に禁じていた実装。`opacity` で足りる）

#### 不採用: 全コンテンツへの一律適用（「とりあえず全部ふわっと」）

**最大の問題: ページ全体が「スクロールしないと存在しないコンテンツ」の集合になり、読む速度・操作手段の違うユーザーほど不利益が大きい。**

**その他の問題:**

- LCP・CLS への悪影響が広範囲に及ぶ
- 演出の価値も薄まる（すべてが動くと何も目立たない）
